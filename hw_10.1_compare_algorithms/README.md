# Coin Change Algorithms

## Завдання
Розробити дві функції для касової системи, яка видає решту покупцеві:
1. **Жадібний алгоритм (`find_coins_greedy`)**
   - Вибирає найбільший доступний номінал монети.
   - Повертає словник із кількістю монет кожного номіналу.

2. **Алгоритм динамічного програмування (`find_min_coins`)**
   - Будує оптимальне рішення через таблицю мінімальних кількостей монет.
   - Завжди знаходить мінімальну кількість монет.
   - Повертає словник із номіналами та їх кількістю.

---

## Приклад роботи

Для суми **113**:

- `find_coins_greedy(113)` → `{50: 2, 10: 1, 2: 1, 1: 1}`
- `find_min_coins(113)` → `{50: 2, 10: 1, 2: 1, 1: 1}`

---

## Порівняння ефективності

### Жадібний алгоритм
- **Складність**: `O(n)`, де `n` — кількість номіналів.
- Дуже швидкий навіть для великих сум.
- Підходить для валют із "правильними" наборами монет (наприклад, 1, 2, 5, 10, 25, 50).
- У реальних касових апаратах застосовується саме цей метод.

### Динамічне програмування
- **Складність**: `O(amount × n)`.
- Гарантовано знаходить мінімальну кількість монет.
- При великих сумах (наприклад, сотні тисяч) працює значно повільніше, бо потрібно заповнювати таблицю розміром `amount`.
- Корисне для нестандартних систем монет, де жадібний алгоритм може дати не оптимальне рішення.

## Тест продуктивності

| Сума   | Жадібний алгоритм | Динамічне програмування |
|--------|-------------------|--------------------------|
| 1 000  | ~0.000002 сек.    | ~0.0007 сек.            |
| 10 000 | ~0.000002 сек.    | ~0.0070 сек.            |
| 20 000 | ~0.000002 сек.    | ~0.0106 сек.            |

---

## Висновки
- **Жадібний алгоритм**: швидший, простіший, оптимальний для стандартних валют.
- **Динамічне програмування**: універсальніше, завжди знаходить оптимальне рішення, але менш ефективне для великих сум.
- У реальних платіжних системах використовується жадібний алгоритм, оскільки він забезпечує швидкість і достатню оптимальність.
